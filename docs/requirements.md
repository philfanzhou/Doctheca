# DocRetrieval 业务需求文档

> 本文档**只描述业务**，不涉及任何技术选型、架构、接口、存储或实现方式。
>
> 任何与"怎么做"有关的内容，请参考 [spec.md](./spec.md)（规格说明）。

## 1. 业务背景

### 1.1 现状与痛点

学生在学习英文教材、做英文真题时，会遇到以下典型问题：

- **生词无处安放**：做阅读时遇到生词，常常需要同时记"它在哪本教材/哪份试卷里出现"和"它在原文中的原句"。当前流程依赖手工抄写或记忆，容易丢失上下文。
- **真题变体难追溯**：同一个单词/短语在不同年份的真题中可能有不同考法。学生做完一道题想"找同类题复习"时，没有便捷的途径。
- **教材定位成本高**：想把"今天背的生词"回放到"它在教材哪一页的哪一句"中，目前需要人工翻页查找，体验差。
- **学习资料无串联**：教材、试卷、错题本是三套独立信息，没有统一的"按词找原文"通路。

### 1.2 业务价值

提供一个**面向英文学习场景的文档检索底座**，使得：

- 学生输入一个单词 / 短语，可以秒级拿到"它出现在哪份文档的哪一页、哪一句、哪道题"
- 教师 / 系统可以基于检索结果做"真题推送"、"PDF 导出"、"错题回放"等下游业务
- 所有学习资料在"按词定位"这个维度上被串成一条通路

## 2. 业务目标

| 目标 | 说明 |
|------|------|
| G1. 按词定位 | 输入单词 / 短语，能返回它出现的所有文档、页码、原句 |
| G2. 按短语定位 | 输入完整短语，能返回包含该短语的句子（不拆碎） |
| G3. 按题定位 | 对于试卷类文档，能定位到"该词出现在哪道题" |
| G4. 同义召回 | 输入一个表达，能返回意思相近的句子/题目 |
| G5. 上下文回放 | 给定一个命中点，能拿到"原句 + 前后文 + 所在题" |
| G6. 可被消费 | 检索结果能被上层业务（错题、真题推送、PDF 导出等）直接消费 |

## 3. 服务定位与调用方

### 3.1 服务定位

本服务是**面向内部微服务体系的检索底座**，**不直接面向终端用户**：

- ❌ 不直接服务于学生 / 教师 / 家长 / 管理员等终端用户
- ❌ 不提供面向 C 端的 Web / App / 小程序入口
- ✅ 仅通过 gRPC 接口被**其它后端微服务**调用
- ✅ 调用方拿到检索结果后，再以各自的方式呈现给最终用户

### 3.2 服务调用方

> 本节描述"谁会调用本服务"，而不是"谁最终看到结果"。

| 调用方 | 调用的能力 | 用途 |
|--------|------------|------|
| 背单词服务 | 精确检索、命中上下文 | 给出生词的"教材 / 真题"出处 |
| 错题服务 | 精确检索、命中上下文 | 在错题页反查"该表达在教材里怎么用" |
| 真题推送服务 | 语义召回 | 为已做过的题推送"同类题" |
| PDF 导出服务 | 命中上下文批量获取 | 导出"生词本对应的所有原句"为 PDF |
| 教师备课工具后端 | 精确检索 + 过滤 | 备课场景下按"教材 / 年级 / 学科"过滤 |
| 资料管理后台 | 文档导入、导入任务状态查询 | 提交 / 删除 / 分类教材与真题 |

### 3.3 非调用方（明确不直接对接）

- 学生 / 教师 / 家长 / 管理员等终端用户 → 始终通过调用方间接使用
- 任何前端 SPA / 移动端 / 小程序 → 不得直接调用本服务
- 任何第三方系统 / 外部合作方 → 通过 API 网关 + 业务中转服务访问，不由本服务直接暴露

## 4. 核心业务场景

> 以下场景均以"上游业务系统 → 调用本服务"的形式描述。**学生 / 教师不直接调用本服务**，他们看到的最终体验由上游系统组装。

### 4.1 场景 A：生词自动提取后的回放

- **触发**：上游"背单词服务"在某终端用户动作中识别出新生词
- **流程**：
  1. 背单词服务记录该生词
  2. 背单词服务调用本服务，按"单词"检索
  3. 本服务返回该生词在教材 / 真题中出现的所有位置
  4. 背单词服务把命中结果以"原文链接"形式呈现给终端用户
  5. 终端用户点击任一链接，触发上游再次调用本服务"取上下文"接口，进入原文上下文
- **业务结果**：终端用户能在"单词 ↔ 原文"之间双向跳转

### 4.2 场景 B：教材定位（原句展示）

- **触发**：上游"背单词 / 备课工具"在终端用户点击"查看教材例句"时
- **流程**：
  1. 上游服务收到终端用户的"按教材过滤"请求
  2. 上游调用本服务"精确检索"，传入单词 + 教材过滤条件
  3. 本服务返回该单词在指定教材中出现的命中
  4. 上游服务把每条命中渲染为"教材名、页码、原句、所在段落"
- **业务结果**：终端用户拿到"教科书级别的例句"，而非词典释义

### 4.3 场景 C：真题推送（同类题）

- **触发**：上游"真题推送服务"在终端用户做完一道题后
- **流程**：
  1. 上游服务从题目中提取关键词或主题
  2. 上游调用本服务"语义召回"能力
  3. 本服务返回意思相近、考法相近的题目列表
  4. 上游服务把题目列表推送给终端用户
- **业务结果**：终端用户获得"举一反三"的练习

### 4.4 场景 D：错题回放

- **触发**：上游"错题服务"在终端用户查看错题详情时
- **流程**：
  1. 错题服务从错题中提取关键词
  2. 错题服务调用本服务，反查"该关键词在哪些教材 / 真题中出现过"
  3. 本服务返回带锚点的命中
  4. 错题服务在错题页内嵌"原文出处"链接
  5. 终端用户点击链接时，由错题服务再次调用本服务"取上下文"
- **业务结果**：错题与原文可联动

### 4.5 场景 E：PDF 导出

- **触发**：上游"PDF 导出服务"在终端用户点击"导出复习材料"时
- **流程**：
  1. 上游服务聚合多个检索命中（可能是多个单词的命中集合）
  2. 上游调用本服务"按锚点取上下文"能力
  3. 本服务返回每个锚点对应的原文 + 上下文
  4. 上游服务组装 PDF 内容并生成下载
- **业务结果**：终端用户得到一份可打印、可分享的复习材料

## 5. 调用方故事

> 格式：`作为 [调用方]，我想要 [能力]，以便 [业务价值]。`
>
> ⚠️ 本节**只描述调用方（其它后端微服务）**的诉求，不描述终端用户故事。终端用户故事由各调用方在自己的需求文档中维护。

### 5.1 通用调用方

- **US-G1** 作为任意调用方，我想要以"原子 gRPC API"的方式调用检索能力（不绑定 UI），以便嵌入到背单词、错题、PDF 导出等任何业务流。
- **US-G2** 作为任意调用方，我想要导入文档时能查询"导入任务状态"，以便上游 UI 展示进度。
- **US-G3** 作为任意调用方，我想要"按锚点拿到原文上下文"，以便在 PDF / 错题页中嵌入可点击的原文链接。
- **US-G4** 作为任意调用方，我想要检索结果支持"按教材 / 年级 / 学科 / 年份"过滤，以便精确服务于不同业务场景。
- **US-G5** 作为任意调用方，我想要检索结果带"页码 + 段落 + 句 / 题"等定位信息，以便在自有 UI 中完整还原原文上下文。

### 5.2 背单词服务（专项）

- **US-V1** 作为背单词服务，我想要按"单词"精确检索该词出现的所有文档与位置，以便在用户查看生词时给出"教材 / 真题"出处。
- **US-V2** 作为背单词服务，我想要按"短语"检索时返回包含该短语的完整句子，以便学习短语用法。

### 5.3 错题服务（专项）

- **US-M1** 作为错题服务，我想要从错题题干中反查"该关键词在哪些教材 / 真题中出现过"，以便在错题页内嵌"原文出处"链接。

### 5.4 真题推送服务（专项）

- **US-P1** 作为真题推送服务，我想要基于题目主题做"语义召回"，以便为已做过的题推送"同类题"。

### 5.5 PDF 导出服务（专项）

- **US-X1** 作为 PDF 导出服务，我想要批量按锚点取原文上下文，以便把"生词本对应的所有原句"组装为 PDF。

### 5.6 教师备课工具后端（专项）

- **US-T1** 作为教师备课工具后端，我想要快速按"单词 + 教材"过滤检索结果，以便挑选典型例句做讲义。
- **US-T2** 作为教师备课工具后端，我想要检索结果能按"年级 / 学科 / 年份"做精切过滤，以便精准备课。

### 5.7 资料管理后台（专项）

- **US-A1** 作为资料管理后台，我想要提交新文档时拿到"导入任务 ID"，以便在管理 UI 中跟踪该文档的解析 / 索引进度。
- **US-A2** 作为资料管理后台，我想要查询导入失败原因（如 OCR 失败、解析超时），以便决定是重传、修正还是下架该文档。

## 6. 业务验收口径

> 以下是"业务视角"的成功标准，**不涉及性能数值、可用率等技术指标**（技术指标见 [checklist.md](./checklist.md)）。
>
> 验收方式：以"调用方能否顺利完成其业务闭环"作为标尺。

### 6.1 必达项

- ✅ 任意调用方传入一个单词，能返回它出现的文档列表、页码、所在句
- ✅ 任意调用方传入一个短语，能返回包含该短语的完整句子（不能拆碎短语）
- ✅ 对扫描件类试卷，能返回该单词所在题目文本
- ✅ 检索结果可还原到"页码 + 段落 + 句 / 题"
- ✅ 任意调用方都能通过统一的 gRPC 接口消费检索能力，无需关心底层细节
- ✅ 至少能同时服务 3 个上游调用方（背单词、错题、真题推送）而不互相干扰

### 6.2 期望项

- 🌟 输入一个表达，能返回意思相近的句子/题目（语义召回）
- 🌟 检索结果支持"按教材 / 年级 / 学科 / 年份"过滤
- 🌟 调用方拿到命中后，能再次调用本服务"取上下文"接口，跳转到原文上下文
- 🌟 错题、真题推送、PDF 导出等业务流能基于本服务实现端到端闭环

## 7. 业务范围

### 7.1 包含

- 英文教材（电子版 PDF / Word / 扫描件）
- 英文考试真题（电子版 / Word / 扫描件）
- "按词 / 按短语 / 按题"的检索能力
- 检索结果中的"页码、句、题"等定位信息
- 文档导入与导入任务状态
- 命中锚点的上下文获取

### 7.2 不包含

- 中文 / 其它语种教材（**首版不覆盖**，作为后续扩展）
- 聊天式问答 / 自由对话
- 单词释义、翻译、词性分析（**由其它服务负责**，本服务只做"位置与原文"）
- 学生学习数据 / 错题数据 / 答题记录（**由其它服务负责**）
- 文档内容的二次创作 / 改写
- 文档版权合规审查
- 用户账号 / 权限管理（**由 Identity 服务负责**）

## 8. 业务术语表

| 术语 | 业务含义 |
|------|----------|
| 文档 | 一份英文教材或考试真题（PDF / Word / 扫描件） |
| 单词 | 调用方按"单词"粒度查询时使用的检索单位 |
| 短语 | 由多个单词组成的固定或半固定表达（如 "take notes"），按"短语"粒度查询 |
| 命中 | 一次检索的返回条目，对应"某词在文档某处出现" |
| 锚点 | 命中的位置描述（哪份文档 / 哪一页 / 哪一句 / 哪道题） |
| 上下文 | 命中所在的原句及其前后文 |
| 同类题 | 意思或考法相近的题目，由语义召回给出 |
| 导入任务 | 把一份原始文档送入本服务并完成解析的流程 |
| 教材 | 教科书、练习册等学习资料 |
| 真题 | 升学 / 等级 / 模拟考试的真实试题 |
| 调用方 | 直接调用本服务 gRPC 接口的其它后端微服务（背单词、错题、真题推送、PDF 导出、教师备课工具、资料管理后台等） |
| 终端用户 | 最终使用学习产品的人（学生 / 教师 / 家长等），由调用方服务，**不直接调用本服务** |

## 9. 业务约束（仅业务层面）

| 约束 | 业务含义 |
|------|----------|
| 文档类型 | 必须同时支持"电子文本"和"扫描件"，两者都是高频来源 |
| 检索语义 | 必须同时支持"精确词 / 短语"和"语义相近"两类召回 |
| 规模预期 | 中规模（一年内数千份文档），单文档可含上千页 |
| 文档语言 | 首版仅支持英文；其它语种作为后续扩展 |
| 业务可达性 | 检索能力必须能被上层多个业务（错题、真题、PDF 导出）复用，不能独占给某一个业务 |
| 可解释性 | 任何一次命中都必须能"指到原文"，不能只有"可能相关" |

## 10. 与上游需求文档的对应关系

本服务的业务需求来自项目主需求文档（[docs/需求文档-英语错题分析与词汇学习系统.md](../../../requirements-英语错题分析与词汇学习系统.md)），对应主线如下：

| 项目主需求 | 本服务对应能力 | 由哪个调用方承接 |
|------------|----------------|------------------|
| 生词自动提取 | 提供"按词定位原文"的能力，供提取流程消费 | 背单词服务 |
| 教材定位 | 场景 4.2：教材定位（原句展示） | 背单词 / 教师备课工具 |
| 原句展示 | 场景 4.1 / 4.2 / 4.4 系列 | 背单词 / 错题服务 |
| 真题推送 | 场景 4.3：真题推送（同类题） | 真题推送服务 |
| PDF 导出 | 场景 4.5：PDF 导出 | PDF 导出服务 |

> 上游主需求文档中"用户"层面的描述，由对应的调用方在其需求文档中落地；本服务只承接其中"按词 / 按短语 / 按题定位原文"这一**底层检索能力**。

## 11. 变更与扩展

- 若业务范围扩大（如新增中文支持、新增文档类型、新增调用方），应**先更新本需求文档**，再驱动规格与实现变更。
- 业务验收口径（§6）是变更的"硬约束"，不得在未更新本需求文档的情况下被技术实现绕过。
- 本服务不直接面向终端用户；任何"终端用户层面的能力扩展"由调用方承接，不应反向要求本服务改造为 C 端接口。
