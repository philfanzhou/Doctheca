# DocRetrieval 业务需求文档

> 本文档只描述业务能力，**不涉及任何技术选型、架构、接口协议、存储与实现方式**。
> 业务流程（谁在什么时机做什么、状态如何流转）见 [process.md](./process.md)；
> 怎么做请参考 [spec.md](./spec.md)。

## 1. 业务背景

学生在学习英文教材、做英文真题时，常常需要"按词回原文"：看到一个生词或短语，希望快速知道"它出现在哪份文档的哪一页、所在句或所在题是什么"。

当前没有统一的检索底座，上游多个业务各自为战。本服务提供一个**只做四件事**的检索底座：

1. **导入文档**：把英文教材 / 真题 / 讲义等文件送进来
2. **查询定位**：按单词 / 短语，拿到"在哪份文档的哪一页的哪个句 / 哪道题"
3. **查询导入状态**：跟踪导入任务的进度与结果
4. **删除文档**：把已经不需要的文档从检索底座中移除

## 2. 服务定位

- 本服务是**面向后端微服务**的检索底座，**不直接面向终端用户**。
- 终端用户（学生 / 教师 / 家长等）由上游业务系统服务，**不直接调用本服务**。
- 任何前端 / 第三方系统都应通过上游业务中转，不得直接调用本服务。

## 3. 能力范围

### 3.1 支持的文档类型

导入接口支持以下文档类型：

| 类型 | 说明 |
|------|------|
| PDF | 包含电子版 PDF 与扫描型 PDF（扫描件走 OCR） |
| Word | `.doc` / `.docx` |
| PPT | `.ppt` / `.pptx` |

### 3.2 对外提供的能力

| 能力 | 用途 |
|------|------|
| 导入文档 | 上游把一份英文文档送进本服务 |
| 查询定位 | 上游传入单词 / 短语，得到"文档 + 页码 + 句 / 题" |
| 查询导入状态 | 上游跟踪导入任务的进度与结果 |
| 删除文档 | 上游把一份已导入的文档从检索底座中移除 |

> 本服务**不提供**聊天、释义、翻译、改写、用户态、权限等能力。这些由其它服务负责。

## 4. 接口说明

### 4.1 导入接口

- **入参**：一份文档文件 + 元数据（可选：教材名 / 学科 / 年级 / 年份 / 标签等）
- **返回**：导入任务 ID（用于跟踪进度）
- **行为**：
  - 解析文档内容
  - 抽取页码、段落、句子、题目边界
  - 建立可被"查询接口"使用的索引
- **支持格式**：`PDF`（含扫描件）/ `Word` / `PPT`（详见 §3.1）

### 4.2 查询接口

- **入参**：
  - `query`：要查的**单词**或**短语**
  - 可选过滤：教材名 / 学科 / 年级 / 年份 等
- **返回**：命中列表，每条命中包含：
  - **文档名**：该命中来自哪份文档
  - **页码**：出现在第几页
  - **关联文本**：该词 / 短语所在的**句子**（普通文档）或**题目**（试卷类文档）
- **行为**：
  - 支持单词查询、短语查询
  - 短语查询必须返回**完整短语命中**，不得拆碎
  - 大小写、词形做归一化（具体规则由规格说明约束）
  - 返回结果按相关度排序

### 4.3 删除接口

- **入参**：文档标识（导入时使用的文档名）
- **返回**：成功 / 失败 + 业务可读的失败原因
- **行为**：
  - 按"文档名"找到对应的文档
  - 标记为"已删除"（软删除）
  - 从检索索引中移除（不可再被查询）
  - 不会清空原始文件与历史任务记录
- **支持状态**：任何状态下的文档都可被删除（导入中 / 已就绪 / 已失败）

> 上游需要保证"文档名"在其业务范围内的唯一性。如果上游希望用其它标识删除，约定在 [spec.md](./spec.md) 中扩展。

## 5. 查询结果示意

> 以下仅为业务字段示意，**不指定具体协议 / 字段名**（由 [spec.md](./spec.md) 决定）。

一次查询返回多条命中，每条命中至少含 3 个业务字段：

| 字段 | 业务含义 |
|------|----------|
| 文档名 | 该命中所在文档的名称 |
| 页码 | 该命中所在页 |
| 关联文本 | 该词 / 短语所在的**句子**（教材类）或**题目文本**（试卷类） |

示例：上游调用"查询 'encourage'"，可能拿到以下命中（简化）：

| 文档名 | 页码 | 关联文本 |
|--------|------|----------|
| 人教版高中英语必修一 | P23 | "Teachers should encourage students to ask questions." |
| 2023 年高考英语全国卷 I | P5（题 21） | "The author aims to encourage readers to ..." |
| ... | ... | ... |

## 6. 业务验收口径

> 仅"业务视角"，不涉及性能 / 可用率等技术指标（见 [checklist.md](./checklist.md)）。

### 6.1 必达项

- ✅ 上游能导入 PDF（含扫描件）/ Word / PPT 三类文档
- ✅ 上游能按"单词"查询，返回该词所在的文档名 + 页码 + 关联文本
- ✅ 上游能按"短语"查询，返回包含该完整短语的句 / 题（不拆碎）
- ✅ 试卷类文档查询时，关联文本为"该词所在题目"
- ✅ 教材类文档查询时，关联文本为"该词所在句子"
- ✅ 上游能查询导入任务的状态（成功 / 失败 / 进行中）
- ✅ 上游能按"文档名"删除一份已导入的文档
- ✅ 已被删除的文档在查询结果中不再出现

### 6.2 不在本期范围

- ❌ 中文 / 其它语种（首版仅支持英文）
- ❌ 聊天式问答
- ❌ 单词释义、翻译、词性分析
- ❌ 文档内容改写 / 二次创作
- ❌ 用户账号、权限管理
- ❌ 文档批量删除（首版只支持单文档按"文档名"删除）
- ❌ 删除后恢复 / 撤销
- ❌ 物理清空已删除文档的存储与历史

## 7. 业务约束

| 约束 | 业务含义 |
|------|----------|
| 文档类型 | 至少支持 PDF（含扫描件）/ Word / PPT 三类 |
| 文档语言 | 首版仅支持英文 |
| 规模 | 中规模（一年内数千份文档），单文档可含上千页 |
| 检索语义 | 至少支持"精确词 / 短语"，可选支持"语义相近"召回 |
| 命中可解释 | 每次命中必须能"指到原文所在的句 / 题"，不得只给"可能相关" |
| 文档标识 | 上游按"文档名"作为业务唯一标识；同名重复导入按业务策略处理 |

## 8. 业务术语表

| 术语 | 业务含义 |
|------|----------|
| 文档 | 一份导入本服务的文件（PDF / Word / PPT 等） |
| 文档名 | 上游按"业务唯一"原则指定的文档名称，是查询过滤与删除的主键 |
| 单词 | 上游按"单词"粒度查询时使用的检索单位 |
| 短语 | 由多个单词组成的固定或半固定表达（如 "take notes"） |
| 关联文本 | 命中所在的"句子"（教材类）或"题目文本"（试卷类） |
| 命中 | 一次查询的返回条目，对应"某词 / 短语在文档某处出现" |
| 导入任务 | 把一份文档送入本服务并完成解析 / 建索引的完整流程 |
| 上游 | 直接调用本服务接口的其它后端微服务 |
| 终端用户 | 最终使用学习产品的人（学生 / 教师 / 家长等），**不直接调用本服务** |
| 软删除 | 标记为"已删除" + 从检索索引移除，但保留原始数据，可由上游重新发起导入 |

## 9. 与上游需求 / 业务流程的对应

本服务的业务需求来自项目主需求文档 [docs/需求文档-英语错题分析与词汇学习系统.md](../../../requirements-英语错题分析与词汇学习系统.md)，对应主线如下：

| 项目主需求 | 本服务对应能力 |
|------------|----------------|
| 生词自动提取 | 导入 + 查询接口，供提取流程消费 |
| 教材定位 | 查询接口（按教材过滤 + 返回句） |
| 原句展示 | 查询接口返回的"关联文本" |
| 真题推送 | 查询接口在试卷类文档上返回"题目" |
| PDF 导出 | 批量调用查询接口获取"关联文本" |
| 教材下架 / 错题文档清理 | 删除接口（按文档名） |

> 上游主需求文档中"用户"层面的描述由上游业务系统承接；本服务只承接"按词 / 按短语定位原文"以及"按文档名删除"这两类底层能力。

## 10. 业务不变式

下面这些是**业务层面的硬约束**，技术实现不得绕过：

1. **每条命中可指回原文**：返回的 `关联文本` 必须是文档中真实存在的句子 / 题目。
2. **短语查询不拆碎**：返回的命中中，`关联文本` 必须**完整包含**用户传入的短语。
3. **粒度不串台**：教材类返回句，试卷类返回题；不允许在教材上返回"题"，也不允许在试卷上返回"段落"。
4. **未就绪不可查**：未成功导入的文档不能出现在任何查询结果中。
5. **已删除不可查**：被软删除的文档不能出现在任何查询结果中。
6. **状态单调收敛**：导入任务一旦成功，不得再变为失败（即使后续索引服务故障，本服务也必须以"任务视角"对外负责）。
7. **本服务永远不持有用户态**：任何调用方认证 / 权限 / 配额都由上游负责。

## 11. 变更规则

- 若业务范围扩大（新增文档类型、文档语言、新增能力），应**先更新本需求文档**，再驱动规格与实现变更。
- 业务验收口径（§6）和业务不变式（§10）是变更的"硬约束"，不得在未更新本需求文档的情况下被技术实现绕过。
