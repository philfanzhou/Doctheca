# DocRetrieval 业务流程设计文档

> 本文档只描述**业务层面**的流程：参与者、流转顺序、状态、异常分支。
> 业务需求（做什么、做到什么程度）见 [requirements.md](./requirements.md)；
> 技术实现（用什么协议、什么存储、什么排序）见 [spec.md](./spec.md)。

## 1. 文档定位

| 文档 | 视角 | 回答的问题 |
|------|------|------------|
| [requirements.md](./requirements.md) | 业务需求 | 做什么、为谁做、做到什么程度 |
| **process.md（本文）** | 业务流程 | 谁在什么时机做什么、状态如何流转、错了怎么办 |
| [spec.md](./spec.md) | 技术规格 | 用什么协议、什么存储、什么算法实现上述流程 |

> 业务范围变更优先改 `requirements.md`，业务流程变更改本文档，技术实现变更改 `spec.md`。

## 2. 业务角色与边界

| 角色 | 性质 | 与本服务的关系 |
|------|------|----------------|
| **Web 管理界面** | 文档管理入口（本服务自带） | 上传 / 删除 / 查看导入状态 |
| **业务系统** | 查询能力消费者（其它后端微服务） | 只能调用查询定位 gRPC 接口 |
| **本服务（DocRetrieval）** | 提供者 | 解析 / 建索引 / 检索 / Web 管理界面 |
| **终端用户** | 最终受众 | **不直接访问本服务**，由业务系统服务 |

**关键约束**：

- 本服务**自带 Web 管理界面**，供管理员 / 运营人员管理文档。
- 本服务**不主动通知**任何人（不推送、不回调、不发事件）。
- 业务系统**只能调用查询接口**，不能上传 / 删除文档。
- 终端用户由业务系统服务，不直接访问本服务或 Web 管理界面。

## 3. 业务流程总览

本服务对外暴露**三条业务流**：

| # | 业务流 | 触发方式 | 同步/异步 | 谁触发 |
|---|--------|----------|-----------|--------|
| ① | 文档导入流 | Web 管理界面上传 | 同步受理 + 异步处理 | 管理员 / 运营人员 |
| ② | 查询定位流 | 业务系统调用 gRPC | 同步 | 业务系统 |
| ③ | 删除文档流 | Web 管理界面删除 | 同步 | 管理员 / 运营人员 |

> **导入状态查看**是 Web 管理界面的伴随功能，不是独立业务流。

三条流的**关系**：

- ① 是 ② 的**前置**：没有被导入并"已就绪"的文档，不能被业务系统查到。
- ③ 与 ② 互斥：被软删除的文档在 ② 中不可见。
- ④ 可作用于任何状态：导入中 / 已就绪 / 已失败的文档都可被删除。

## 4. 核心业务流程

### 4.1 文档导入流

**业务目标**：把一份英文文档（PDF / Word / PPT，含扫描件）转化为"可被业务系统查询的检索底座"。

#### 4.1.1 触发时机

由管理员 / 运营人员通过 Web 管理界面操作：

- 上传一份教材 / 真题 / 讲义
- 批量上传一批文档
- 周期任务触发上传（Web 管理界面配置）

#### 4.1.2 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 管理员 | 在 Web 管理界面选择文件 + 填写必填元数据（教材名 / 学科 / 年级 / 年份） |
| 2 | 管理员 | 点击"上传" |
| 3 | 本服务 | 校验必填元数据 + 校验教材名是否已存在（重名拒绝），通过后生成**导入任务 ID** 并立即在界面展示 |
| 4 | 本服务 | 异步执行：解析 → 抽取页码 / 段落 / 句子 / 题目 → 建索引 |
| 5 | 管理员 | 在 Web 管理界面查看导入状态（进行中 / 成功 / 失败） |
| 6 | 本服务 | 导入成功后，该文档可被业务系统通过 gRPC 查询到 |

#### 4.1.3 关键业务规则

- **导入是异步的**：本服务只承诺"收到并受理"，不承诺"立即可查"。
- **元数据必填**：教材名 / 学科 / 年级 / 年份为必填项，未填写时界面拦截。
- **重名拒绝**：教材名已存在时，立即拒绝上传，不得进入异步阶段。
- **不支持的格式**必须立即拒绝，不得进入异步阶段。

### 4.2 查询定位流

**业务目标**：业务系统传入"一个词 / 一个短语"，本服务返回该词 / 短语在哪些**已就绪且未删除**文档的哪一页、所在的句 / 题是什么。

#### 4.2.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 业务系统 | 准备入参：`query`（必填，单词或短语）+ 可选过滤（教材名 / 学科 / 年级 / 年份 等）+ 分页参数（`page_size`，默认 50，最大 100；`page_token`） |
| 2 | 业务系统 | 调用本服务**查询定位 gRPC 接口** |
| 3 | 本服务 | **归一化**（大小写、词形） |
| 4 | 本服务 | 执行检索（精确匹配 + 可选语义召回） |
| 5 | 本服务 | **去重**（同一页同句 / 同题的多处出现合并为一条） |
| 6 | 本服务 | **排序**（按相关度） |
| 7 | 本服务 | 构造**命中列表**返回业务系统 |
| 8 | 业务系统 | 消费命中：在自己的产品里展示"原句" / 还原"题号" / 收集"导出条目" |

#### 4.2.2 关键业务规则

- **短语必须完整命中**：查 "take notes" 不得返回 "take ... notes ..." 这种被拆碎的命中。
- **粒度由文档类型决定**（详见 `requirements.md §4.3`）：
  - 教材 / 讲义类 → 关联文本是**句子**。
  - 试卷类 → 关联文本是**题目文本**。
- **大小写与词形归一化**是本服务责任，业务系统不需要提前处理。
- **过滤维度的语义**由业务系统传入的元数据决定；本服务不做"猜你想查哪个学科"。
- **未就绪的文档不参与查询**：导入未成功的文档不能被查到。
- **已删除的文档不参与查询**：被软删除的文档不能被查到。
- **无命中**不是错误：返回空列表即可，业务系统决定如何展示。

### 4.3 删除文档流

**业务目标**：管理员 / 运营人员通过 Web 管理界面把不再需要的文档从检索底座中移除，使其不再出现在任何查询结果中。

#### 4.3.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 管理员 | 在 Web 管理界面选择要删除的文档（按"教材名"） |
| 2 | 管理员 | 点击"删除" |
| 3 | 本服务 | 按"教材名"查找对应文档 |
| 4 | 本服务 | 标记为"已删除"（软删除） |
| 5 | 本服务 | 从检索索引中移除该文档的全部条目 |
| 6 | 本服务 | 返回成功 / 失败 + 业务可读的失败原因，Web 管理界面展示 |

#### 4.3.2 关键业务规则

- **同步执行**：删除是轻量操作（标记 + 索引移除），不引入任务 ID 跟踪。
- **支持任意状态**：导入中 / 已就绪 / 已失败的文档都可被删除；删除导入中的文档会取消其后续处理。
- **幂等**：对同一文档名重复删除，最终结果一致（"已删除"）。
- **可重导**：被软删除的文档，原始文件与历史任务记录保留；管理员可通过 Web 管理界面重新上传，使用同名即视为新一份文档入库。
- **不影响其它文档**：删除 A 不会触碰 B 的任何数据。

## 5. 业务状态机

### 5.1 导入任务状态机

```
                  ┌──────────┐
                  │  待处理   │（任务已受理，尚未开始解析）
                  └────┬─────┘
                       │ 开始解析
                       ▼
                  ┌──────────┐
        ┌────────▶│  进行中   │（解析 / OCR / 建索引 中某一阶段）
        │         └────┬─────┘
        │              │ 完成
        │              ▼
        │         ┌──────────┐
        │         │  成功     │（文档已"就绪"，可被业务系统查询）
        │         └──────────┘
        │ 失败重试
        │              │ 失败
        │              ▼
        │         ┌──────────┐
        └─────────│  失败     │（带失败原因，文档不可被查询）
                  └──────────┘
```

**业务规则**：

- 状态终态：`成功` / `失败`；两者不可互相转化。
- `失败` 状态下，管理员可通过 Web 管理界面**重新上传**（新建任务），不修改原任务。
- 任意非终态的查询返回 `进行中`（及当前阶段信息），不会出现"未知状态"。

### 5.2 文档可消费状态

文档"能否被业务系统查询到"由其**最新一个成功导入任务**与**是否被删除**共同决定：

| 状态 | 含义 | 对业务系统的影响 |
|------|------|-----------------|
| 未就绪 | 有任务但未成功，或没有任务 | gRPC 查询不可见 |
| 已就绪 | 至少一个导入任务处于"成功"，且**未被软删除** | gRPC 查询可见 |
| 已删除 | 文档被 Web 管理界面标记为软删除 | gRPC 查询不可见 |

**状态切换驱动**：

```
未就绪 ───导入成功──▶ 已就绪 ───Web 管理界面删除──▶ 已删除
  ▲                                                      │
  │                                                      │
  └──────────────Web 管理界面重新上传（同名新建任务）─────┘
```

> 重新上传不是"恢复"，而是按"文档名"作为业务主键，**新建一份**文档入库。已删除文档的历史任务记录不会被覆盖。

## 6. 异常与降级分支

| 异常场景 | 业务流程表现 | 处理建议 |
|----------|--------------|----------|
| 文件格式不在 §3.1 范围 | Web 管理界面**立即提示不支持** | 管理员换格式或联系技术支持 |
| 必填元数据缺失（教材名 / 学科 / 年级 / 年份） | Web 管理界面**立即拦截** | 管理员补填元数据 |
| 教材名已存在（重名） | Web 管理界面**立即拒绝**，原因"教材名已存在" | 管理员换名或删除旧文档后重新上传 |
| 文件损坏 / 解析失败 | 任务进入 `失败`，带原因"解析失败" | 管理员重新上传或人工介入 |
| 扫描件 OCR 失败（质量过差） | 任务进入 `失败`，带原因"OCR 失败" | 管理员上传更清晰的扫描件 |
| 索引失败 | 任务进入 `失败`，带原因"索引失败" | 管理员重新上传 |
| 业务系统查询无命中 | gRPC 正常返回**空列表**（非错误） | 业务系统展示"暂无原文命中" |
| 业务系统传入空 query / 非英文 | gRPC 同步拒绝（业务校验） | 业务系统在校验层处理 |
| Web 管理界面删除时教材名不存在 | 删除接口**同步返回失败**，原因"文档不存在" | 界面提示 |
| Web 管理界面删除时教材名已被删除 | 删除接口**同步返回成功**（幂等） | 界面无需特别提示 |
| Web 管理界面删除时索引移除失败 | 删除接口**同步返回失败**，原因"索引清理失败"；文档状态仍保持"未删除"，可重试 | 管理员重试 |
| 业务系统传入 page_size > 100 | gRPC 返回错误（业务校验失败） | 业务系统调整参数 |

## 7. 变更规则

- **业务范围扩大**（新增能力 / 新增文档类型 / 新增语种）：先改 [requirements.md](./requirements.md)，再改本文档，最后改 [spec.md](./spec.md)。
- **业务流程优化**（不变更业务范围，仅优化步骤顺序 / 异常分类）：直接改本文档，并在 [checklist.md](./checklist.md) 中追加对应验收项。
- **任何技术实现上的优化**（不改变业务流）：只改 [spec.md](./spec.md)，**不得回流到本文档**。
