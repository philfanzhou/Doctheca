# DocRetrieval 业务流程设计文档

> 本文档只描述**业务层面**的流程：参与者、流转顺序、状态、异常分支。
> 业务需求（做什么、做到什么程度）见 [requirements.md](./requirements.md)；
> 技术实现（用什么协议、什么存储、什么排序）见 [spec.md](./spec.md)。

## 1. 文档定位

| 文档 | 视角 | 回答的问题 |
|------|------|------------|
| [requirements.md](./requirements.md) | 业务需求 | 做什么、为谁做、做到什么程度 |
| **process.md（本文）** | 业务流程 | 谁在什么时机做什么、状态如何流转、错了怎么办 |
| [spec.md](./spec.md) | 技术规格 | 用什么协议、什么存储、什么算法实现上述流程 |

> 业务范围变更优先改 `requirements.md`，业务流程变更改本文档，技术实现变更改 `spec.md`。

## 2. 业务角色与边界

| 角色 | 性质 | 与本服务的关系 |
|------|------|----------------|
| **上游业务系统** | 消费者（其它后端微服务） | 调用本服务的导入 / 查询 / 状态 / 删除四类接口 |
| **本服务（DocRetrieval）** | 提供者 | 只响应上游请求，不主动外呼 |
| **被处理的文档** | 业务对象 | 由上游交付、由本服务解析 / 建索引 / 软删除 |
| **终端用户** | 最终受众 | **不直接调用本服务**，由上游业务系统服务 |

**关键约束**：

- 本服务**永远不直面终端用户**，没有用户态、登录态、权限态。
- 本服务**不主动通知**上游（不推送、不回调、不发事件），仅在被查询时给出当前状态。
- 上游负责把"用户行为"翻译成"对 DocRetrieval 的请求"。

## 3. 业务流程总览

本服务对外暴露**四条业务流**，分别对应 `requirements.md §3.2` 的四类能力：

| # | 业务流 | 对应能力 | 同步/异步 |
|---|--------|----------|-----------|
| ① | 文档导入流 | 导入文档 | 同步受理 + 异步处理 |
| ② | 文档查询流 | 查询定位 | 同步 |
| ③ | 导入状态跟踪流 | 查询导入状态 | 同步 |
| ④ | 删除文档流 | 删除文档 | 同步 |

四条流的**关系**：

- ① 是 ② 的**前置**：没有被导入并"已就绪"的文档，不能被查询。
- ③ 是 ① 的**伴随**：导入是耗时异步过程，上游必须能跟踪其状态。
- ④ 与 ② 互斥：被软删除的文档在 ② 中不可见。
- ④ 与 ① 互不阻塞：删除进行中（极短）时，**已就绪**的文档仍可被查询。
- ④ 可作用于任何状态：导入中 / 已就绪 / 已失败的文档都可被删除。

## 4. 核心业务流程

### 4.1 文档导入流

**业务目标**：把上游持有的一份英文文档（PDF / Word / PPT，含扫描件）转化为"可被查询接口消费的检索底座"。

#### 4.1.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 上游 | 收集"一份文档文件 + 元数据"（教材名 / 学科 / 年级 / 年份 / 标签等，可选） |
| 2 | 上游 | 调用本服务**导入接口** |
| 3 | 本服务 | 校验入参（类型 / 大小 / 是否英文等业务层校验），生成**导入任务 ID** 并立即返回 |
| 4 | 本服务 | 异步执行：解析 → 抽取页码 / 段落 / 句子 / 题目 → 建索引（具体技术细节见 `spec.md`） |
| 5 | 上游 | 拿到任务 ID 后，进入"导入状态跟踪流"（见 §4.3） |
| 6 | 上游 | 当状态变为"成功"后，可对该文档发起查询 |

#### 4.1.2 关键业务规则

- **导入是异步的**：本服务只承诺"收到并受理"，不承诺"立即可查"。
- **元数据是过滤维度**：上游传入的教材名 / 学科 / 年级 / 年份必须**全量透传至查询阶段**，作为命中过滤的合法维度。
- **不支持的格式**必须立即拒绝（同步返回失败），不得进入异步阶段。

### 4.2 文档查询流

**业务目标**：上游传入"一个词 / 一个短语"，本服务返回该词 / 短语在哪些**已就绪且未删除**文档的哪一页、所在的句 / 题是什么。

#### 4.2.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 上游 | 准备入参：`query`（必填，单词或短语）+ 可选过滤（教材名 / 学科 / 年级 / 年份 等） |
| 2 | 上游 | 调用本服务**查询接口** |
| 3 | 本服务 | **归一化**（大小写、词形；具体规则见 `requirements.md §4.2` 与 `spec.md`） |
| 4 | 本服务 | 执行检索（精确匹配 + 可选语义召回） |
| 5 | 本服务 | **去重**（同一页同句 / 同题的多处出现合并为一条） |
| 6 | 本服务 | **排序**（按相关度） |
| 7 | 本服务 | 构造**命中列表**返回上游 |
| 8 | 上游 | 消费命中：在自己的产品里展示"原句" / 还原"题号" / 收集"导出条目" |

#### 4.2.2 关键业务规则

- **短语必须完整命中**：查 "take notes" 不得返回 "take ... notes ..." 这种被拆碎的命中。
- **粒度由文档类型决定**（详见 `requirements.md §4.2`）：
  - 教材 / 讲义类 → 关联文本是**句子**。
  - 试卷类 → 关联文本是**题目文本**。
- **大小写与词形归一化**是本服务责任，上游不需要提前处理。
- **过滤维度的语义**由上游传入的元数据决定；本服务不做"猜你想查哪个学科"。
- **未就绪的文档不参与查询**：导入未成功的文档不能被查到。
- **已删除的文档不参与查询**：被软删除的文档不能被查到。
- **无命中**不是错误：返回空列表即可，上游决定如何展示。

### 4.3 导入状态跟踪流

**业务目标**：让上游能确认"那份文档导入得怎么样了"。

#### 4.3.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 上游 | 拿任务 ID 调用**状态查询接口** |
| 2 | 本服务 | 返回当前状态（进行中 / 成功 / 失败）+ 业务可见的进度信息（如"解析中"、"建索引中"） |
| 3 | 上游 | 根据状态决定下一步：继续轮询 / 标记文档可消费 / 触发重试 / 告警 |

#### 4.3.2 关键业务规则

- 状态值必须**单调收敛**：进行中 → 成功 / 失败，不得在成功后回退为进行中。
- 失败时必须给出**业务可读**的失败原因分类（格式不支持 / 文件损坏 / OCR 失败 / 索引失败 等），但**不暴露**技术栈细节。
- 已成功的任务其状态不可变；如需"再导入一次"，必须创建新任务。

### 4.4 删除文档流

**业务目标**：把上游不再需要的文档从检索底座中移除，使其不再出现在任何查询结果中。

#### 4.4.1 流程步骤

| 步骤 | 主体 | 业务行为 |
|------|------|----------|
| 1 | 上游 | 准备入参：`文档名`（导入时使用的业务唯一标识） |
| 2 | 上游 | 调用本服务**删除接口** |
| 3 | 本服务 | 按"文档名"查找对应文档 |
| 4 | 本服务 | 标记为"已删除"（软删除） |
| 5 | 本服务 | 从检索索引（OpenSearch / 向量库）中移除该文档的全部条目 |
| 6 | 本服务 | 返回成功 / 失败 + 业务可读的失败原因 |

#### 4.4.2 关键业务规则

- **同步执行**：删除是轻量操作（标记 + 索引移除），不引入任务 ID 跟踪。
- **支持任意状态**：导入中 / 已就绪 / 已失败的文档都可被删除；删除导入中的文档会取消其后续处理。
- **幂等**：对同一文档名重复删除，最终结果一致（"已删除"）。
- **可重导**：被软删除的文档，原始文件与历史任务记录保留；上游可重新发起导入，导入时使用同名即视为新一份文档入库。
- **不影响其它文档**：删除 A 不会触碰 B 的任何数据。

## 5. 业务状态机

### 5.1 导入任务状态机

```
                  ┌──────────┐
                  │  待处理   │（任务已受理，尚未开始解析）
                  └────┬─────┘
                       │ 开始解析
                       ▼
                  ┌──────────┐
        ┌────────▶│  进行中   │（解析 / OCR / 建索引 中某一阶段）
        │         └────┬─────┘
        │              │ 完成
        │              ▼
        │         ┌──────────┐
        │         │  成功     │（文档已"就绪"，可被查询）
        │         └──────────┘
        │ 失败重试
        │              │ 失败
        │              ▼
        │         ┌──────────┐
        └─────────│  失败     │（带失败原因，文档不可被查询）
                  └──────────┘
```

**业务规则**：

- 状态终态：`成功` / `失败`；两者不可互相转化。
- `失败` 状态下，上游可选择**新建任务**重试（业务层面），不修改原任务。
- 任意非终态的查询返回 `进行中`（及当前阶段信息），不会出现"未知状态"。

### 5.2 文档可消费状态

文档"能否被查询到"由其**最新一个成功导入任务**与**是否被删除**共同决定：

| 状态 | 含义 | 上游行为 |
|------|------|----------|
| 未就绪 | 有任务但未成功，或没有任务 | 不得在面向用户的功能中暴露"可查" |
| 已就绪 | 至少一个导入任务处于"成功"，且**未被软删除** | 可作为查询目标 |
| 已删除 | 文档被上游调用删除接口标记为软删除 | 同"未就绪"，且无法通过导入接口之外的任何路径恢复 |

**状态切换驱动**：

```
未就绪 ───导入成功──▶ 已就绪 ───调用删除接口──▶ 已删除
  ▲                                              │
  │                                              │
  └──────────────────重新导入（同名新建任务）──────┘
```

> 重导入不是"恢复"，而是按"文档名"作为业务主键，**新建一份**文档入库。已删除文档的历史任务记录不会被覆盖。

## 6. 异常与降级分支

| 异常场景 | 业务流程表现 | 业务处理建议 |
|----------|--------------|--------------|
| 文件格式不在 §3.1 范围 | 导入接口**同步拒绝** | 上游立即提示"该格式暂不支持" |
| 文件损坏 / 解析失败 | 任务进入 `失败`，带原因"解析失败" | 上游可选择重试或人工介入 |
| 扫描件 OCR 失败（质量过差） | 任务进入 `失败`，带原因"OCR 失败" | 上游可提示用户"请上传更清晰的扫描件" |
| 索引失败 | 任务进入 `失败`，带原因"索引失败" | 上游可触发重试 |
| 查询无命中 | 正常返回**空列表**（非错误） | 上游展示"暂无原文命中" |
| 上游传入空 query / 非英文 | 同步拒绝（业务校验） | 上游在校验层提示 |
| 上游高频轮询状态 | 业务不限制 | 由 `spec.md` 在技术层做频率保护 |
| 文档正在导入中、已被查询请求命中过滤 | 查询正常返回（**不阻塞**） | 上游不必等待导入完成 |
| 删除时文档名不存在 | 删除接口**同步返回失败**，原因"文档不存在" | 上游按"幂等成功"或"未找到"提示 |
| 删除时文档已被删除 | 删除接口**同步返回成功**（幂等） | 上游无需特别处理 |
| 删除时索引移除失败 | 删除接口**同步返回失败**，原因"索引清理失败"；文档状态仍保持"未删除"，上游可重试 |

## 7. 变更规则

- **业务范围扩大**（新增能力 / 新增文档类型 / 新增语种）：先改 [requirements.md](./requirements.md)，再改本文档，最后改 [spec.md](./spec.md)。
- **业务流程优化**（不变更业务范围，仅优化步骤顺序 / 异常分类）：直接改本文档，并在 [checklist.md](./checklist.md) 中追加对应验收项。
- **任何技术实现上的优化**（不改变业务流）：只改 [spec.md](./spec.md)，**不得回流到本文档**。
