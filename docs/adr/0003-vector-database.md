# 3. 向量库选择

## 状态

待决定 (Pending)

## 上下文

DocRetrieval 服务需要语义召回能力，用于：
1. 查找与查询词语义相近的句子/题目
2. 支持混合检索（精确匹配 + 语义召回）

需要评估不同向量库方案的成熟度、易用性、与现有技术栈的兼容性。

## 决策

**待决定**

选项：
1. **Qdrant**（推荐）- 专业向量数据库
2. **pgvector** - PostgreSQL 扩展，利用现有数据库

## 备选方案分析

### 方案 A：Qdrant
- **优点**：
  - 专为向量检索设计，性能更好
  - 功能丰富（过滤、索引类型、距离度量等）
  - 生态成熟
- **缺点**：
  - 新增中间件依赖
  - 需要额外运维成本

### 方案 B：pgvector
- **优点**：
  - 利用现有 PostgreSQL，无需新中间件
  - 数据一致性好（与元数据同库）
  - 运维简单
- **缺点**：
  - 向量检索性能不如专用向量数据库
  - 功能相对有限
