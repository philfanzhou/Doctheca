# 文档管理技术设计

## 设计重点

- 列表查询与状态查看走 PostgreSQL
- 元数据修改后同步刷新 OpenSearch / Qdrant 的过滤字段
- 删除时要保证数据库、对象存储、索引三处状态尽量一致

## 文档列表

- 主数据源：`documents`
- 典型过滤字段：
  - `title`
  - `subject`
  - `grade`
  - `year`
  - `status`

## 元数据修改

- 修改入口只允许更新可编辑字段
- 文档名与文件哈希不可进入写模型
- 更新数据库后立即触发索引元数据同步

## 删除一致性

- 数据库删除：删除 `Document` 及其关联实体
- 对象存储删除：删除 SeaweedFS 原始文件
- 精确索引删除：按 `document_id` 清理 OpenSearch
- 向量索引删除：按 `document_id` 清理 Qdrant

## 关键风险

- 索引清理失败会导致“数据库已删但查询还能命中”的不一致
- 元数据同步失败会导致过滤字段失真
- 删除导入中任务时，需要 Worker 感知取消
